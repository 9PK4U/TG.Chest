# Восстановление данных TG.Chest

Это копия данных личного Telegram-архива Chest и Mini App.

Содержимое `snapshot.tar.gz`:

- `database.dump`: PostgreSQL целиком — записи, разделы, теги, зашифрованный сейф, настройки, метаданные вложений, эмбеддинги и очередь задач.
- `settings.tar.gz`: серверный `.env` с токенами, паролем БД и **FILE_ENCRYPTION_KEY**, реквизиты OAuth-приложения Яндекса, если сохранены на сервере.
- `data.tar.gz`: локальные зашифрованные данные, включая вложения, ожидающие отправки на Диск.
- `inventory.json`: количества строк, версия миграции и ссылки на файлы Диска.

В PostgreSQL также входят таблица `captures` с зашифрованными исходными сообщениями и историей LLM-правок, режимы конфиденциальности заметок и режим бота. Для чтения исходников нужен прежний FILE_ENCRYPTION_KEY. Настройки доверенной модели TRUSTED_AI_* сохраняются вместе с .env; на новом сервере её адрес при необходимости исправляется отдельно.

Таблица `ai_configurations` содержит зашифрованные настройки моделей, сохранённые через Mini App, включая API-ключи и прокси. Они имеют приоритет над исходными параметрами .env, поэтому после восстановления проверьте адреса/прокси в интерфейсе настроек обоих контуров. Для их расшифровки также нужен прежний FILE_ENCRYPTION_KEY.

Исходники приложения, Docker-образы и образ сервера в копию не входят. Сервис устанавливается отдельно из проекта TG.Chest, затем возвращаются данные. Сохраните проект отдельно. Версия схемы БД указана в `manifest.json`; используйте совместимую версию исходников.

Файлы на Диске лежат в `TG.Chest` как `<id>.enc` и повторно не копируются. Не удаляйте и не переименовывайте их вручную. После удаления записи сервис сохраняет файл, пока он нужен хотя бы одному оставшемуся бекапу.

Архив приватный: внутри действующие токены и ключи. Мастер-пароль сейфа остаётся только у владельца и понадобится после восстановления. Серверный ключ файлов его не заменяет.

## Расписание и выбор копии

Яндекс Диск: папка приложения Chest → TG.Chest → backups (`app:/TG.Chest/backups`). Запуск ежедневно **в 05:00 по Красноярску**. Хранятся копии за 7 суток; последняя успешная остаётся всегда. При ошибке прежние не удаляются, повтор — через 30 минут. Пропущенный при выключенном сервере запуск выполняется после включения.

Выберите свежую папку `chest-YYYYMMDDTHHMMSSZ-xxxxxxxx` с **COMPLETED.json** (время UTC). Скачайте её целиком: `snapshot.tar.gz`, `manifest.json`, `COMPLETED.json`, `restore.py` и эту инструкцию. Большие базы могут сохраняться частями `snapshot.part-0001` и далее; скрипт соберёт их автоматически. Маркер COMPLETED появляется после проверки размера и SHA-256 загруженных файлов.

## Восстановление на чистом сервере

Нужны Linux, Docker Compose, Python 3.12+, доступ к реестрам контейнеров, свободные порты 5432 и 80/443. Остановите прежнего бота. Скрипт отказывается работать при существующих томах `tg-chest_postgres_data` или `tg-chest_chest_data`, чтобы не затронуть действующие данные. Не удаляйте рабочие тома ради запуска скрипта.

1. Установите исходный проект в `/opt/tg-chest`, **не запускайте сервисы**. Скачанную копию положите, например, в `/root/chest-backup`.
2. Проверьте копию:

   ```bash
   python3 /root/chest-backup/restore.py --backup /root/chest-backup --verify-only
   ```

3. Восстановите данные:

   ```bash
   sudo python3 /root/chest-backup/restore.py --backup /root/chest-backup --target /opt/tg-chest
   ```

   Скрипт проверит контрольные суммы, вернёт `.env`, соберёт приложение из установленных исходников, запустит PostgreSQL 17 с pgvector, восстановит БД и локальные зашифрованные данные. Бот, API и worker пока выключены. Штатные миграции применяются при последующем запуске.
4. Проверьте `.env`: домен, PUBLIC_URL, прокси. Сохраните прежние FILE_ENCRYPTION_KEY и `YANDEX_DISK_ROOT=app:/TG.Chest`. Если токен Яндекса отозван, получите новый **для прежнего OAuth-приложения**, иначе папка app:/ будет другой. Реквизиты приложения находятся в восстановленном `yandex-client.secrets.json`.
5. Настройте DNS и доступ к Telegram/OpenRouter. Раньше Telegram использовал HTTP-прокси `127.0.0.1:7890`, API/worker — `metacubexd:7890` в Docker-сети gateway. Укажите доступный прокси или очистите TELEGRAM_PROXY / OPENROUTER_PROXY, если доступ работает напрямую.
6. Запустите сервис. На чистом сервере HTTPS обслуживает Caddy:

   ```bash
   cd /opt/tg-chest
   docker compose -f compose.yaml up -d --build
   ```

   Если уже настроены прежние nginx, gateway и metacubexd, используйте `docker compose -f compose.yaml -f compose.gateway.yaml up -d --build` и `deploy/chest.nginx.conf`. Общая инфраструктура VDS настраивается отдельно.
7. Проверьте /api/health, бот и Mini App, записи, сейф с прежним мастер-паролем и скачивание вложения.
8. Включите расписание:

   ```bash
   sudo install -m 644 /opt/tg-chest/deploy/tg-chest-backup.service /etc/systemd/system/
   sudo install -m 644 /opt/tg-chest/deploy/tg-chest-backup.timer /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now tg-chest-backup.timer
   sudo systemctl start tg-chest-backup.service
   ```

   При другом пути проекта исправьте пути в service-файле.

## Ручное восстановление

Проверенный snapshot содержит database.dump, settings.tar.gz, data.tar.gz, inventory и инструкцию. В чистом PostgreSQL **17 с pgvector** восстановите дамп через `pg_restore --exit-on-error --no-owner --no-acl`. Верните .env из settings, содержимое data — в том tg-chest_chest_data, владелец UID 10001. Путь внутри контейнера остаётся /app/data. До восстановления данных не запускайте бот и worker. Задачи running верните в pending с locked_until=0.

Проверка расписания и ошибок:

```bash
systemctl list-timers tg-chest-backup.timer
journalctl -u tg-chest-backup.service -n 50 --no-pager
```
